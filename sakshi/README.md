# SAKSHI

> デザインがデザインシステムに沿って作られているかを監査する Figma プラグイン

**公開範囲**: 組織内リリース（Figma Community には公開していない）

---

## 概要

選んだフレームの中で、ライブラリのコンポーネント・スタイル・Variables が意図どおりに使われているかを調べて報告する。
ルールにもとづくチェックが基本で、必要なときだけ Gemini による解析を加えられる。

「SAKSHI」はサンスクリット語で「目撃者・純粋な観察者」。判断の基準は利用者が決め、プラグインはそれに沿って観察する、という考え方から名付けた。構造を直す [SATORI](../satori/) と対になっている。

| プラグイン | 役割 | 視点 |
|---|---|---|
| **SATORI** | 1 フレームの構造を直す | 虫の目 |
| **SAKSHI** | デザインシステムに沿っているかを監査する | 鳥の目 |

**開発期間**: 2026年6月  
**開発形態**: 個人開発（AI を活用）  
**対応環境**: Figma

---

## 主な機能

| 機能 | 概要 |
|---|---|
| **ライブラリの確認** | コンポーネントライブラリが使われているか |
| **壊れたインスタンス** | 元のコンポーネントが失われたインスタンス（常に検出） |
| **ライブラリ外のコンポーネント** | チームライブラリではなく、ファイル内のコンポーネントを使っている箇所 |
| **スタイル未適用の色** | 対応するカラースタイルがあるのに、色を直接指定している箇所。対応するスタイル名も表示 |
| **未承認の色（任意）** | デザインシステムにない色を使っている箇所 |
| **テキストスタイル未適用** | テキストスタイルがあるのに使っていない文字 |
| **Variables 未適用** | カラーの Variables があるのに紐づけていない塗り |
| **AI 解析（任意）** | Variant の選び方やコンポーネントの使い方が一貫しているかを Gemini で判断 |
| **結果の整理** | ルール別 / ノード別の表示切替、検索、重要度での絞り込み、CSV 書き出し |
| **ルールの ON / OFF** | チームの運用に合わせて、各チェックを有効・無効にできる |

## 技術スタック

| 分類 | 技術 |
|---|---|
| 言語 | TypeScript |
| プラットフォーム | Figma Plugin API（チームライブラリ、Variables） |
| AI（任意） | Gemini API（画像 + レイヤー構造） |
| 外部 API | Figma REST API（チームライブラリのスタイルの照合） |
