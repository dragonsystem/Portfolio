## Phase 4 — Token Store と Variables 同期

### なぜ作ったか

それまで色・間隔・角丸はコードに直接書かれており、ブランドカラーを変えるにはコードを書き換えるしかなかった。
「デザイナーが自分のブランドで使えるプラグイン」にするための中心となる機能として、Token Store を作った。

### 範囲の決め方

| 含める | 含めない |
|---|---|
| ブランドカラー 4 色 | error / warning などの機能色（固定） |
| 間隔の基準値 | 文字サイズのスケール |
| 角丸の 4 段階（Sharp / Default / Rounded / Circular） | アニメーション |
| フォント名 | 太さ・行間の個別調整 |

事前にコードを調べた結果、想定より実装量が少なく済むとわかり、データの土台 → 画面 → フォント の 3 段階に分けて進めた。

## 公開後の開発（未公開）

公開版とは別の開発用リポジトリで開発を続けている。ここに書く内容はまだ公開していない。

### 進め方

- 作業はチケット単位（ブランドアセット BR、ページテンプレート PT、マスター再生成 MR など）
- 大きな機能はフェーズごとに計画書を書き、承認してから実装する
- 作業日ごとに状況の記録を残し、次に再開する場所を「引き継ぎ」ファイルにまとめる
- 実装のたびに型チェック・ビルド・テストを通し、Figma 上での確認まで行う

### デザインの考え方を文書化（2026-07-22）

- 境界の表し方の優先順位を決めた：**余白 → 面 → 影 → 罫線**（罫線は最後の手段）
- 影の色を純粋な黒から、寒色を混ぜた濃い色（`rgb(26,43,77)`）に変える方針を決めた。黒い影は下の面とぶつかって重く見えるため
- 一覧画面を「データの表」ではなく、オブジェクトを起点に設計する方針（OOUI）をまとめた
- 色の計算や間隔のスケールなど Sutra 固有の考え方を、ほかのプロジェクトでも使える形（AI 向けのスキル）に切り出した

### コンポーネントの一括作り直し（2026-08-23）

マスターコンポーネントは「設計（スキーマ）が変わったときだけ作り直す」仕組みだった。描画のコードだけを直しても、既存ファイルのマスターは古いまま残り、原因を突き止めるのに 1 時間近くかかった。
そこで全マスターを作り直すボタンを追加した。押した時点では印を付けるだけにし、次にコンポーネントを置いたときに作り直す。その場で全部作り直すと、処理が長く止まるため。

あわせて、3 種類のリセットボタンの名前を、何が戻るのかがわかる表記に直した。

### React 出力（2026-08-24〜10-12）

Figma のコンポーネントを React + Tailwind のコードに変換し、zip で書き出す機能。

| Phase | 内容 |
|---|---|
| 0〜2 | 変換処理を Figma に依存しない形で作り、Button で検証 |
| 3〜6 | 基本部品（Atom）20 件すべてに対応。画面から zip で書き出せるようにした |
| 7 | Figma 側と出力コードのずれを検査（色・寸法） |
| 8〜9 | 部品を組み合わせた部品（Molecule）に対応。子の部品は `import` で組む |
| 10 | 色・枠線を Variant 単位、ノード単位で照合 |
| 11 | 子要素の hover / pressed の色に対応 |
| 12 | Card など大きな部品（Organism）に対応。2026-10 時点で 55 件 |

#### 決めたこと

| 問い | 選択 | 理由 |
|---|---|---|
| 部品の組み合わせ方 | 子の部品を `import` で組む | コードを展開してしまうと、子のデザインを変えるたびに使っている箇所をすべて直すことになる |
| 見出しの要素名（h1〜h6） | 文字サイズとは別の設定にする | 見出しのレベルは文書の構造の問題で、見た目の大きさとは別に決めたい |
| 変換の仕組みの拡張 | 1 つ入れるたびに、既存の出力が 1 バイトも変わっていないかを確認 | 意図しない変化を混ぜないため |

#### 実際の React で試してわかったこと

書き出したコードを実際の React プロジェクトとして動かしたところ、構文・型チェック・描画はすべて通った。そのうえで 2 つの漏れが見つかった。

- ある部品の色が、使っているトークンの一覧から抜けていた
- 部品の説明書（manifest）に、`children` や `value` など一部の設定項目が載っていなかった。説明書だけを読む AI には、その項目が見えない状態だった

ここから得た教訓は「**コードが動くことと、説明が正しいことは別**」。これをきっかけに、Figma 側のデザインと出力コードを自動で突き合わせる検査（Phase 7 以降）を作った。2026-09 時点の確認では 20 件中 17 件が完全に一致し、残りの差の理由も特定できた。
