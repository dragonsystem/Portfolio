# OOUI プラグイン群（Modeler / Modeler Pro / View View）

> オブジェクト指向 UI（OOUI）の設計を、モデリングからワイヤーフレームまで Figma 上でつなぐ 3 本のプラグイン

**公開範囲**: 組織内リリース（Figma Community には公開していない）

---

## 概要

OOUI（Object-Oriented User Interface）は、画面やタスクからではなく、ユーザーが扱う**オブジェクト（名詞）**から UI を設計する手法である。
実践するには、業務の説明からオブジェクトを抜き出し、プロパティ・アクション・関係を整理し、それをもとに一覧画面と詳細画面を組み立てる必要がある。この工程は手作業が多く、設計を変えるたびに図とドキュメントがずれていく。

この 3 本は、その工程を Figma 上で 1 本の流れにする。

```
業務の説明（自然言語）          AI との対話で作ったモデル（Mermaid）
        │                              │
        ▼                              ▼
   ┌─────────┐                   ┌─────────────┐
   │ Modeler │                   │ Modeler Pro │
   └────┬────┘                   └──────┬──────┘
        └──────────┬───────────────────┘
                   ▼
     Figma 上のオブジェクトカード（共通の形式）
                   │
                   ▼
            ┌───────────┐
            │ View View │
            └─────┬─────┘
                  ▼
   ワイヤーフレーム（一覧画面・詳細画面・アプリの枠）
```

| プラグイン | 対象 | 役割 |
|---|---|---|
| **Modeler** | OOUI の初級〜中級者 | 業務の説明を入力すると、AI がオブジェクトモデルを推論して Figma / FigJam に描く |
| **Modeler Pro** | OOUI の上級者 | 自分で AI と対話して作ったモデル（Mermaid）を読み込み、同じ形式で描く。AI はアクションと担当者（アクター）の補完だけに使う（任意） |
| **View View** | 共通 | 描かれたオブジェクトカードを読み取り、ワイヤーフレームを自動生成する |

**開発期間**: 2026年5月〜6月  
**開発形態**: 個人開発（AI を活用）  
**対応環境**: Figma / FigJam

## 主な機能

### Modeler

| 機能 | 概要 |
|---|---|
| **オブジェクトの推論** | 業務の説明から、オブジェクト・プロパティ（型つき）・アクション・関係を AI が抽出 |
| **キャンバスへの描画** | オブジェクトごとにカードを描く。FigJam では関係を矢印で結ぶ |
| **既存モデルの更新** | 描いたカードを読み戻し、AI の提案と比べて「上書き」か「追加」かをオブジェクトごとに選べる |
| **仕様ブロック** | 元にした業務の説明と、関係の一覧を毎回キャンバスに残す |
| **書き出し** | TypeScript の型定義、Markdown の仕様表、用語集（ユビキタス言語）、Mermaid の ER 図 |

### Modeler Pro

| 機能 | 概要 |
|---|---|
| **Mermaid の取り込み** | `.md` ファイルのドロップ、またはテキストの貼り付けでモデルを読み込む |
| **表記ゆれへの対応** | 軽いゆれは自動で直し、構造の問題は一覧で見せて「続行 / 中止」を選ばせる |
| **AI による補完（任意）** | 足りないアクションと、それを行う担当者（アクター）を推論。オブジェクトごとに適用するかを選べる |
| **Mermaid への書き戻し** | Figma 上で手直ししたカードを、Mermaid として書き出し直せる |
| **プロンプトのテンプレート** | AI との対話を始めるとき用と、決まったモデルを Mermaid に変換するとき用の 2 種類 |

### View View

| 機能 | 概要 |
|---|---|
| **一覧画面（Collection View）** | テーブル型 / カード型。並べ替えの印、選択列、ページ送りつき |
| **詳細画面（Single View）** | 入力フォーム型 / 表示型。プロパティの型に合わせた入力部品（文字・数値・日付・切り替え・選択） |
| **担当者ごとの画面** | アクターごとに、その人が見るプロパティだけで画面を作る |
| **関係の表示** | 関係するオブジェクトを、詳細画面の中にテーブルやカードで表示 |
| **アプリの枠（App Shell）** | サイドバー / 上部ナビゲーション |
| **Auto Layout** | 生成した画面はすべて Auto Layout で組まれ、そのまま手直しできる |

## 技術スタック

| 分類 | 技術 |
|---|---|
| 言語 | TypeScript |
| プラットフォーム | Figma Plugin API（Figma / FigJam） |
| ビルド | Vite + vite-plugin-singlefile、esbuild |
| AI | Gemini API（Modeler：必須 / Modeler Pro：任意 / View View：不使用） |
| プラグイン間の連携 | `sharedPluginData`（名前空間 `ooui`）と、共通仕様書（Modeler Spec） |

規模: TypeScript 約 2,700 行（3 本の合計）。

## AI 活用の効果（自己見積もり）

開発後、同じものを人のエンジニアが作った場合の工数と、実際にかかった時間を比べて記録した。

| プラグイン | エンジニアが単独で作る場合（見積もり） | 実際の作業時間（プロデューサー） |
|---|---|---|
| Modeler | 約 30〜35 人日 | 約 12〜18 時間 |
| View View | 約 25〜35 時間 | 約 8〜12 時間 |

※ いずれも開発記録をもとにした概算。プロデューサーの時間は、要件の言語化・動作確認・判断にかけた時間。
