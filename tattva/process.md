## 開始時点の状態

2026-05-29 の時点で、アプリは次のような状態だった。

- 1 回の API 呼び出しで出力し、区切り文字で 2 つのファイルに分けていた
- ダイアグラムは mermaid を CDN から読み込んでおり、サンドボックスで表示されなかった
- ダイアグラムは BLUEPRINT.md の図しか表示していなかった
- ファイル保存がサンドボックスの仕組みに沿っておらず、実際には保存されていなかった
- Git で変更履歴を管理していなかった

## 2026-05-29 — 不具合修正と機能追加

### 不具合修正

| 問題 | 対処 |
|---|---|
| ダイアグラムが表示されない | mermaid.js をアプリに同梱。DESIGN.md の図も表示対象に |
| BLUEPRINT.md が生成されない | API 呼び出しを 2 回に分割 |
| ファイルが保存されない | セキュリティスコープブックマークに対応 |
| mermaid の構文エラー | サニタイザー・プロンプトの制約・エラー通知 |

### 優先度順の改善

| 優先度 | 内容 |
|---|---|
| Priority 1（信頼性） | 生成状況の表示（1/2・2/2）、自動リトライ、mermaid のエラー通知 |
| Priority 2（品質） | Google Stitch 適合度チェック |
| Priority 3（使い勝手） | Context テンプレート、生成履歴、マルチウィンドウ |
| Priority 4 の前 | API キーの Keychain 移行、キーボードショートカット、画像の拡大表示 |

### DESIGN.md の品質改善

生成した DESIGN.md を Gemini で評価したところ、「完成度 80〜85%」で、次の不足が指摘された。

| 不足点 | 内容 |
|---|---|
| フォント | 「情報不足のため定義保留」がそのままフォント名として出力される |
| 状態色 | 「少し暗くする」のような文章での記述 |
| 影 | `shadows:` がなく、コンポーネントから参照できない |
| 値の直書き | コンポーネントに hex 値が直接書かれ、二重管理になる |

プロンプトだけでは根本的に解決できないと認識したうえで、制約を追加して改善した（フォント名の「保留」を禁止、hover / active / disabled の色を必須に、`shadows:` / `transitions:` を追加、コンポーネントはトークン参照に統一）。

## 意思決定ログ

| 問い | 選択 | 理由 |
|---|---|---|
| API エラー時の再試行 UI | 失敗したボタンのラベルを Retry に変える | UI を増やさず、どのパターンが失敗したかがすぐわかる |
| DESIGN / BLUEPRINT の分離 | API 呼び出しを 2 回に | AI の出力のぶれに左右されない。コストより確実さを優先 |
| ファイル名の大文字・小文字 | `DESIGN.md` のまま | Google Stitch の公式表記に合わせる |
| 保存フォルダ名 | `yyyyMMdd_HHmmss` 形式 | Unix タイムスタンプは人が読めない |
| チェック結果の表現 | 「エラー」→「改善推奨」「確認推奨」 | 生成結果は使えないものではなく、品質の差であるため |
| 履歴の配置 | サイドバー → エディタ上部のツールバー（時計アイコン） | 内容が切り替わる場所の真上にある方が自然。履歴がなければアイコンを隠す |
| ズームの範囲 | 2%〜2000%、倍率に比例したステップ | 「小さくて読めない」状態をなくす |
