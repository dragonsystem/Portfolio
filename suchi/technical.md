# Suchi — 技術的な工夫

## アーキテクチャ方針

- **外部依存ゼロ**: CocoaPods / SPM を使わず Apple 純正フレームワークのみで完結
- **iOS 17+ 専用**: `@Observable`, SwiftData, MapKit for SwiftUI など最新 API を積極採用
- **真北基準の統一**: 方位はすべて真北基準。矢印回転は `(目的地方位角) - (端末 Heading)` を -180..180 に正規化して累積することでラップアラウンド（359°→0°）に対応

---

## 長押しピン — 精度と体感の作り込み

実機フィードバックで「ピンが意図した位置と少しずれる」「長押し中に地図が反応してしまう」問題が発覚し、複数の対策を重ねた。

### 1. ジェスチャーの配置場所

`.mapControls`・`.safeAreaPadding`・`.ignoresSafeArea` より**前**、`Map` 直下にジェスチャーを付与することで、座標系のズレによる設置位置ズレを解消した。

### 2. タッチ位置の知覚補正

指が画面に触れる接触点は、ユーザーが「ここを押している」と感じる位置より下にある。
local タッチ座標を**上へ 22pt 補正**してから地図座標へ変換することで、意図した場所にピンが落ちるよう調整した。

### 3. ライブプレビューピン

0.3 秒で長押し成立と同時にピンを表示し、指を離すまで追従させる（Apple Maps / Google Maps のピン落とし方式）。
長押し時間も 0.4 秒 → 0.3 秒に短縮。

### 4. 押下フィードバックリング

タップ・パン時には反応せず、**0.1 秒静止後に出現し、残り 0.2 秒で満ちてピン設置**となるリングアニメーションを実装。
「いまどのくらいで設置されるか」がひと目でわかる。位置固定・1 回きりのアニメーションで地図操作を重くしない軽量実装。

### 5. 二本指操作との競合解消

`.gesture` → `.simultaneousGesture` に変更し、地図のパン/ズーム/回転とジェスチャー競合判定が起きる「待たされ」を解消した。

## コンパス — 軽量化と北向きリセット

### 純正 MapCompass の置き換え

`MapCompass(scope:)` をオーバーレイで表示する方式は回転描画が重かったため、**自前の軽量ダイヤ針**（北=赤 / 南=薄灰）に置換し、左上へ独立配置した。

### 北向きリセットの実装

`.region` で方位 0 を設定する方式が不発になる問題を、**方位を 0 にした `MapCamera` を直接設定**する方式で解消した。
ズームや傾きは変更せず、方位のみをリセットする。

## ナビ画面 — 横向き対応とコンパス精度警告

### 端末の向き追従

`headingOrientation` を固定値ではなく **`UIDevice` の向き通知**に追従させた。
これを固定にすると横向き時に矢印が 90 度ズレる。現在の認識向きを枠＋上端マーカーの記号インジケーターで表示している。

### 横向きレイアウト

コンパス類のサイズ基準を短辺に変更し、横向き時は左コンパス・右情報の 2 カラムレイアウトへ自動切替。

### コンパス調整警告の誤検出解消

「Heading が 5 秒途絶」で警告を出す設計は、直進・静止中の誤検出が多かった。  
**`headingAccuracy` が無効または誤差 30 度超の状態が 3 秒継続**したときだけ警告するよう変更し、iOS 標準のキャリブレーション画面表示を許可した。

## 天体照合（GeoAstro）

太陽・月の方位をコンパスリングに重ねて表示し、車体の金属による磁気干渉をその場で確認できる機能。

```
GeoAstro
    └─ 現在地 (lat, lon) + 現在時刻（UTC 基準）
         ├─ 太陽の方位角・仰角を計算
         └─ 月の方位角・仰角を計算
              └─ CompassRing に重ねて表示
```

**UTC 基準**で計算することが重要。JST のまま計算すると 9 時間ズレた方位が出る典型バグになる。

## 多言語対応（String Catalog）

### 設計方針

| 決定事項 | 内容 |
|---|---|
| `developmentRegion` | `en` → `ja` に是正（日本語が原文のため） |
| キー設計 | 意味のあるキー（`map.*` / `nav.*` / `log.*` / `about.*`）。日本語をキーにしない |
| 距離単位 | 「言語」ではなく**「地域（`Locale.current.measurementSystem`）」**に従う |
| 言語切り替え | アプリ内設定から iOS 設定へ誘導（`openSettingsURLString`） |

### 距離単位のロケール追従

英語 UI × 日本地域 → メートル表記のまま（距離は言語でなく地域に従うため正しい挙動）。  
「数値 + 半角スペース + 単位」の形式を維持（ナビ画面が数値と単位を分割描画するため）。

### 位置情報許可ダイアログの挙動

L-9 の実装中に判明した事実:
**アプリ言語を英語にしても、許可ダイアログは端末言語に従う。**
OS が別プロセスでダイアログを描画するため、`InfoPlist.xcstrings` にロケール別の文言を用意しても、表示言語はアプリ側で制御できない。

## 走行記録の設計

### タイトルの自動生成

距離をタイトルとして表示するのをやめ、**日付ベース + 同日連番**の自動タイトルにした。
（例: 「7月4日」 / 同日2件目は「7月4日\_2」）

### 再ナビのための座標保存

履歴から同じ目的地へ再ナビできるよう、`RouteLog` に `destinationLat` / `destinationLon` を保存している（Export Format v1.2 で追加）。

### JSON エクスポート形式の前後方互換

| バージョン | 追加フィールド |
|---|---|
| v1.0 | 基本フィールド |
| v1.1 | `title`（任意） |
| v1.2 | `destinationLat` / `destinationLon`（任意） |

on-disk の `version` 整数は 1 のまま維持。フィールドは任意追加・null 明示出力・欠如許容で前後方互換を保つ。  
iOS / Android 共通仕様のため、片側だけ変更しない不変条件がある。

## SwiftData の注意点

- `LocationPoint` は順序保証がないため、使用前に必ず `timestamp` でソートする
- `RouteLog` と `LocationPoint` のリレーションは cascade 削除対応（CloudKit を使わないため制約なし）
